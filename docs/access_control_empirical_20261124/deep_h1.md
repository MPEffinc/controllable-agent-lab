# H1 반박 중심 조사: 자연어 요구에서 검증 target으로의 의미 오류

기준일: 2026-11-24. 이 문서는 K06 AutoCedar의 검증 계획이 원래 승인 의도와 어긋날 수 있다는 가설을 **기존 해법으로 먼저 반박**한다. 아래 논문별 숫자는 입력·언어·평가 분모가 서로 달라 성능 순위로 비교하지 않는다. 유료 모델 호출이나 추가 평가 실행은 하지 않았다.

## 고정할 문제와 판정 범위

- **보안 속성:** 신뢰할 수 있는 승인 주체가 허용한 `(주체, 행동, 자원, 조건)`만 정책으로 허용하고, 지정한 금지도 보존해야 한다. 검증 target 자체가 누락되거나 넓어지면, 정책이 그 target에 대해 형식적으로 정확해도 의도에는 어긋난다.
- **정상 업무:** 명시적으로 승인된 접근은 허용되어야 한다. 따라서 거짓 허용과 거짓 거부를 모두 센다.
- **신뢰/공격 모델:** 우선은 고의 공격 없이 모호하거나 불완전한 자연어와 모델의 해석 오류를 다룬다. 공격자가 요구 문서나 인용 근거를 바꿀 수 있는 경우는 별도 모델로 표시해야 한다. 누락된 원래 의도는 주어진 텍스트만으로 복원할 수 없으므로, 독립된 승인 원본이나 사람의 확인 없이 ‘정답’을 입증할 수 없다.
- **구별할 성질:** (1) target–승인 의도 의미 일치, (2) 정책–target의 형식적 동치/포함, (3) 배포 PEP에서의 실제 효과. H1은 (1)에 해당한다. Cedar/SMT의 (2) 성공이나 API 차단의 (3) 성공으로 H1을 해결했다고 판정하지 않는다.

## 원문과 공개 자원으로 확인한 가장 강한 반박

|---|---|---|---|
| **K06 AutoCedar** | 문서에서 스키마·intent·조건 atom을 추출하고 사람 또는 모델이 검토한 뒤, 승인된 atom으로 floor/ceiling 및 실행 가능한 검증 계획을 만든다. Cedar 동치/포함은 그 고정 target에 대해 강한 확인 수단이다. | AutoCedar의 gold 비교가 바로 자기 계획 검증에서 놓친 19건을 드러낸 실증이다. [Cedar 원문 §4–6](https://arxiv.org/abs/2403.04651)과 [공식 symbolic compiler](https://github.com/cedar-policy/cedar-spec)는 주어진 정책/명세 사이의 성질을 검증한다. 독립 원본이 정확한지, 사람이 빠진 문장을 알아채는지는 별도로 확인해야 한다. ‘사람 검토’라는 절차 자체를 무오류 oracle로 취급할 수 없다. | 강한 기존 해결 조합; 독립 원본과 검토자 접근성이 있는 범위에서는 신규 Need 주장의 우선 반박. |
| **Reparo** | 코드·주석·문서에서 승인 근거를 모으고 정책 합성과 **별도의 모델이 생성한 행동 oracle**로 요청별 의미를 비교한다. | [원문 §1, §7, §9](https://arxiv.org/html/2610.41800v1)는 228개 실제 저장소와 390개 수동 검토 oracle 사례를 보고한다. 수동 검토된 oracle test-case의 정확성은 Cedar 93.1%, OpenFGA 96.9%, Rego 91.5%; Cedar oracle rule coverage는 모델별 56.3–70.2%, 결합 70.6–75.3%라고 보고한다. 저자도 정책과 oracle이 **같은 근거를 사용해 함께 틀릴 수 있음**, 근거 누락, 유한 테스트를 인정한다. 이는 독립 gold보다 약하지만 H1의 의미 오류를 직접 겨냥한 기존 대응이다. [저자 공개 목록](https://ayeshathoi.github.io/)에서 논문은 확인했으나 이 조사에서 공식 코드는 확인하지 못했다(`UNKNOWN`). | 직접 대안. 같은 근거의 공통 오류에는 잔여 조건. |

NGAC 조건부 권한의 집행은 별도 애플리케이션 책임인 범위도 있다. 저자는 공개 artifact를 출판 뒤 제공하겠다고 명시하므로 현재 코드 재현으로 간주하지 않는다. | 출처 추적·역번역·검토라는 직접 보완; Cedar 전체 문서 target 보장을 뜻하지 않음. |

### AutoCedar의 19건을 읽는 방법

[K06 원문 §V-A](https://arxiv.org/html/2607.03656v2)의 gold는 43개 도메인의 200사례로, 수작업 skeleton을 확장·검토한 뒤 결정적 컴파일러로 작성했다. 정책 생성 시스템에는 gold를 주지 않았다. 따라서 같은 평가 내에서 **자체 target을 통과한 정책과 별도 참조 정책의 차이**를 관측할 수 있다. 그러나 gold가 모든 실제 조직의 승인 의도를 대표하거나, 사람 검토·Reparo·NGAC-IR을 **동일 19사례**에 적용해도 오류가 남는다는 증거는 아니다. 원문의 직접 생성 132/200과 AutoCedar 178/200도 target 문제를 모두 해결했다는 뜻이 아니다.

## 현재 H1 판정

**넓은 H1: `PARTIALLY_RESOLVED`.** target 의미 오류는 AutoCedar 자체의 19/197 관측과 명시적 한계로 실재한다. 하지만 독립 승인 원본, 권한자 검토, 행동 oracle, 출처 기반 역번역·검토라는 기존 직접 대응이 있다. 형식 도구가 target과 정책의 관계를 정확히 증명할 수 있는 범위도 기존 연구로 해결된다. 이 자료만으로 ‘독립 Research Gap/Need가 있다’고 판정할 수 없다.

**좁은 잔여 가설: `UNVERIFIED`.** 독립 gold가 없는, 여러 출처에서 승인 의도를 추출해야 하는 사례에서 정책과 행동 oracle이 같은 누락·오해를 공유하고, 제한된 검토 예산 아래 출처 기반 검토까지 그 오류를 놓쳐 비인가 효과 또는 정상 작업 거부가 남는가? Reparo §9와 AutoCedar §VI는 이 가능성을 인정하지만, **같은 입력·신뢰 모델·검토 조건에서** 강한 기존 조합이 실패한다는 직접 관측은 아직 없다. 특히 [Reparo §6.1 Table 4](https://arxiv.org/html/2610.41800v1)는 코드·주석·문서를 함께 사용한 12개 Cedar 저장소에서 같은 generated oracle 대비 91.9% 결정 일치, 코드만 63.8%, 문서만 57.9%를 보고한다. 따라서 다중 출처 결합 **자체는 이미 직접 다뤄졌다**. 다만 oracle도 결합 근거에서 생성되어 공통 오류 가능성이 남는다. 빠진 승인 정보 자체는 입력 결손 문제이며, 그 조건만으로 새 기법의 미충족 Need를 주장하지 않는다. 승인 원본이 없다면 권한자에게 묻거나 안전한 기본 거부를 선택하는 것이 기존 대응이다. 후자는 정상 업무 비용을 수반하므로 이를 측정해야 한다.

**기각 조건:** 같은 좁은 조건에서 출처를 아는 사람 검토, 독립 gold/업무 oracle, Reparo식 행동 oracle, NGAC-IR식 역번역과 누락 범위 확인, 혹은 현실적으로 적용 가능한 조합이 target 오류를 허용 가능한 검토 비용과 정상 업무 성공률로 잡아낸다면 신규 gap 가설을 기각한다. 독립 gold가 있으면 그것과 Cedar 동치/포함 검사를 우선 대조한다. 반대로 `GAP_SUPPORTED`로 올리려면 이러한 강한 대조군까지 놓치는 **같은 사례의 실제 오류와 효과**, 입력의 정보 충분성, 실행 가능 비용을 제시해야 한다.

## 다음 최소 검증 질문(아직 실행하지 않음)

**질문:** K06에서 자기 계획 검증을 통과하고 gold와 달랐던 사례를 공개 입력·계획·gold로 특정할 수 있는가? 그중 의미/범위 오류 하나에서 출처 기반 사람 검토, 별도 행동 oracle, 역번역 검토가 같은 오류를 잡는가?

1. 동일 문서·스키마·승인 주체와 gold의 허용/금지 요청을 고정한다. K06 원래 target 및 gold 대비 요청별 결정을 기록한다. 공개 artifact가 19건 개별 식별을 지원하지 않으면 `NOT_ESTABLISHED`로 기록한다.
2. **대조군:** 올바른 target과 원래 target, 독립 gold가 있는/없는 oracle, 출처를 보여주는/보여주지 않는 검토를 구분한다. 모델 비교가 필요하면 무료·허가된 자원과 고정 seed/version만 사용한다. ‘사람 검토’를 실제로 수행하지 않고 검토 성공을 가정하지 않는다.
3. 거짓 허용, 거짓 거부, 확인 요청 수, 검토 시간/비용을 측정한다. 정책 결정만 있으면 `DECISION_ONLY`; 서비스 효과가 있는 경우에만 effect를 따로 주장한다.
4. **종료:** 기존 방법이 오류를 잡으면 해당 잔여 가설을 기각한다. 놓치더라도 source 결손 또는 잘못된 독립 gold 때문이면 가설을 재정의한다. 유료 API 호출이나 규모 있는 평가가 필요해지면 중지하고 필요 자원만 기록한다.

이 문서의 결론은 H1의 가능성을 남기는 `UNVERIFIED`이며, 신규 Research Need 확정은 **0건**이다.
