# D5 사전등록 — ActPlane 원본의 격리 VM eBPF 집행

등록 시점: 2026-11-25 UTC, 실험 전. 고정 원본: `third_party/K13-actplane` SHA `1cbb4d0f40e2bc6042d6883f045fe8e0e838b168`. API 예산 $0. 기존 기록·원본 소스는 수정하지 않는다.

## 질문과 위협 모델

같은 Agent 프로세스가 직접 파일 쓰기 또는 자식 프로세스를 통해 금지 파일에 쓰기를 시도할 때, 원본 ActPlane eBPF Hook이 정상 쓰기는 허용하고 금지 효과를 커널에서 차단하는가? 공격자는 도구 호출 경로를 바꿀 수 있지만 root/정책 관리자는 아니다. VM 안의 실험 파일만 사용한다. 호스트의 LSM 설정, 시스템 서비스, 기존 컨테이너는 변경하지 않는다.

## 예측과 기각 조건

1. 원본 `block write file` 정책의 정상 허용 파일은 변경된다. 금지 파일은 변경되지 않고, 위반 event와 `EPERM`이 관측된다. LSM Hook을 붙일 수 없다면 pre-op 차단은 `NOT_RUN`으로 판정한다.
2. 동일 정책을 자식 프로세스에도 적용할 수 있으면 자식 금지 쓰기도 차단한다. 프로세스 lineage가 정책에 정확히 결속되지 않으면 실패로 기록한다.
3. tracepoint `kill`만 가능할 경우 실제 kernel event 집행은 관측 가능하지만 pre-op 원자성을 주장하지 않는다.
4. 정상 허용이 실패하거나 금지 파일이 바뀌면 이 구성의 안전·정상성 예측을 기각한다. 빌드·VM 부팅·권한·Hook attach 실패는 원인과 마지막 성공 단계, raw stderr를 남기고 결과를 `NOT_RUN`으로 둔다.

## 실행·측정·대조

원본 CLI/loader와 정책 DSL을 변경하지 않고 빌드한다. KVM QEMU의 일회용 guest rootfs에서 `bpf` LSM을 부팅 인자로 활성화해 guest 내부에서만 Hook을 붙인다. 정책/입력은 정상 쓰기, 금지 직접 쓰기, 금지 자식 쓰기 각 1회 이상이다. 파일 해시/내용 전후, exit code, 위반 로그, kernel/LSM 목록, 빌드 SHA와 명령, 소요 시간을 보존한다. 원본 실행과 연구자 실험 드라이버를 분리 표기한다. OpenShell 기존 원본 실행과는 동일 기능의 보장 범위를 비교하며 동일 kernel 실험이라고 표현하지 않는다.

## 제약

호스트는 `CONFIG_BPF_LSM=y`지만 현재 LSM 목록에는 `bpf`가 없고 sudo가 비대화형으로 불가하다. 호스트에 직접 BPF를 attach하지 않는다. VM 부팅이나 빌드가 불가하면 순수 DSL/컴파일 테스트로 실제 집행을 대체하지 않는다. 비용은 로컬 계산·다운로드만 사용하며 유료 LLM 호출은 하지 않는다.
