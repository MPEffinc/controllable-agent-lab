# C6 검증된 정책 정규화 대조

2026-11-25 UTC. [사전등록](prereg.md) 규칙으로 C4/C5의 같은 공식 case-011 gold+연구자 변이 6개를 정규화했다. [원시 모델 기록](raw.jsonl), [정형 verifier 및 전체 verdict](result.json), [실행 코드](run.py), `verify_p0/`–`verify_p6/`, `p0.cedar`–`p6.cedar`를 보존했다.

첫 기술적 preflight는 중복 conjunct의 여는 괄호까지 지워 구문 오류로 멈췄다. `preflight_v1/`에 모든 파일·실패 로그를 보존했고 **모델 호출은 0**이었다. 괄호를 보존하도록 코드만 고친 뒤 동일 사전등록 규칙으로 실행했다. 공식 AutoCedar verifier의 양방향 포함이 **7/7 PASS**여서 정규화 전후 정책 의미가 스키마 범위에서 동일함을 확인했다.

총 14 calls, 입력 3,360/출력 1,318 tokens, 추정 **$0.0103136**. 정규화된 `p0`는 승인됐고 여섯 오류 변이는 모두 거부됐다. 기존 C4의 정상·비인가 Cedar/SQLite 효과와 공식 verifier 동치를 함께 보면, 이 고정 요청에서 정규화는 정책 자체의 안전/정상 범위를 바꾸지 않고 리뷰어의 거짓 거부를 없앴다.

**판정:** C4/C5의 오류는 이 표기 형식에 민감했다. 기존 정형 verifier+간단한 동치 정규화로 해소돼 이 사례의 새 검증 메커니즘 Need는 `REJECTED_HYPOTHESIS`. 단일 공식 case·여섯 연구자 변이와 독립 전체 정책 reviewer에 대한 결과이며, AutoCedar 원본의 atom별 ModelReviewer·사람 검토나 저자 19개 오류의 성능이 아니다. 코퍼스의 유사 표기 빈도와 다른 case에서의 효과는 별도 C7로 검증한다.
