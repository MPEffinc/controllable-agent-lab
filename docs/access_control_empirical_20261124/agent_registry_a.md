## 재현·해석 주의

- K03은 **현재 원저자 artifact 링크가 기존 지시서의 후보 repo와 다르다.** 기존 실험 실행 여부를 버리거나 덮어쓸 이유는 없다. 기존 commit의 코드 흐름과 최신 논문 v3의 artifact를 각각 비교해야 한다.
- K04는 [§V-C Table III](https://arxiv.org/html/2603.17170v2)의 원본/수정 task 분모가 다르다. 초록의 100/100만을 원본 task 성능으로 기록하면 오판이다.
- K07의 원문 명시적 한계를 코드 없는 실험 성공/실패로 취급하지 않는다. 특히 Text2NGAC artifact는 NGAC-IR artifact가 아니다.
- K05 형식 증명의 대상은 Cedar semantics·validator·symbolic compiler이며, 생성된 정책이 사람의 원래 의도와 일치한다는 보장이 아니다. [논문 §3–4](https://arxiv.org/html/2403.04651v2), [Lean 증명](https://github.com/cedar-policy/cedar-spec/tree/main/cedar-lean)
- K06은 [§V-D Table VI](https://arxiv.org/html/2607.03656v2)에서 완료된 정책 197개 모두 생성된 verification plan을 통과했지만 178개만 독립 gold와 동치였다. 나머지 19개는 검증 목표 자체의 경계가 달랐다. 이는 verifier가 틀렸다는 관측이 아니라 목표와 의도 사이의 잔여 오류 관측이다.
- 모든 원격 HEAD는 이번 감사 당시 스냅샷이다. 논문 속 모델·의존성·코드 버전의 일치를 별도 검증하기 전에는 어떤 새 실행도 논문 재현이라 부르지 않는다.

## K06 고정 소스의 target/verifier 추적 (추가 감사)

- 부모 연구 작업이 확보한 `third_party/K06-autocedar`는 위 `a0cf180...` HEAD와 일치한다. [PropertyAtom](../../third_party/K06-autocedar/autocedar/atoms.py)은 `symbolic_verified`와 `intent_acknowledged_by_user`를 별도 필드로 보관한다(183–205행). 전자는 형식 검사, 후자는 검토자의 의미 승인이다. [pipeline](../../third_party/K06-autocedar/autocedar/pipeline.py)은 검토한 intent map의 조건에서 floor/ceiling atom을 만드는 경로를 명시한다(747–751행). 따라서 승인 target이 정확해야 후속 증명의 목적도 정확해진다.
- [CLI](../../third_party/K06-autocedar/autocedar/cli.py)의 `verify workspace`(393–398, 943–960행)는 `run_verification`을 부른다. [orchestrator](../../third_party/K06-autocedar/autocedar/harness/orchestrator.py)는 `workspace/schema.cedarschema`, `candidate.cedar`, `verification_plan.py`를 읽고 먼저 `cedar validate`로 구문·타입을 확인한 뒤 `cedar symcc`로 ceiling 포함(`candidate ≤ ceiling`), floor 포함(`floor ≤ candidate`), liveness, never-errors 등을 검사한다(36–54, 57–169행). [solver wrapper](../../third_party/K06-autocedar/autocedar/harness/solver_wrapper.py)는 CVC5 경로를 인자로 전달한다(17–21, 141–159행). 이 경로 자체에는 모델 API 호출 코드가 없지만 `verification_plan.py`는 Python 모듈로 `exec_module`되므로 실행 전에 그 파일을 확인해야 한다. 제공된 `workspace/verification_plan.py`는 `get_checks()`와 `os.path.join`만 가진 것으로 확인했다.
- 선행 도구: README는 Cedar CLI **4.10.0 + `analyze` feature**의 `symcc`, CVC5, Python ≥3.11을 요구한다([README](../../third_party/K06-autocedar/README.md), 130–186행). 로컬 읽기 전용 확인 결과 Python 3.12.15와 `uv`는 있고, `cedar`, `cvc5`, `cargo`는 PATH 및 해당 기본 설치 경로에 없다. 따라서 `verify workspace`의 실제 통과 여부는 **미실행·미확인**이다. 설치·모델 호출은 이 추가 감사에서 하지 않았다.
