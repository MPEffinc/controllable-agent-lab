# C7 공식 gold 교차 사례의 블라인드 검토

2026-11-25 UTC. [사전등록](prereg.md)에 따라 AutoCedar 공식 gold 200개 중 `(!(true) ||` 포함 **184개**를 읽기 전용으로 확인하고, 50-case 구간별 첫 해당 case `001,052,101,151`을 고정했다. 표기 빈도는 reviewer 오류율이 아니다. [실행 코드](run.py), [모델 원시 16 요청/응답](raw.jsonl), [전체 정형·모델 결과](result.json), 원본/정규화 정책 및 `verify_case-*`를 보존했다. 공식 AutoCedar verifier의 **양방향 포함 4/4 PASS**였다. 따라서 아래 원본과 정규화는 해당 스키마·검사 범위에서 의미가 같다.

| 공식 gold case | mini 원본 → 정규화 | 강한 모델 원본 → 정규화 | 주요 관찰 |
|---|---|---|---|
| `001` | 승인 → 승인 | **거부 → 승인** | 강한 모델이 원본의 `!(true) ||`를 항상 true라고 잘못 해석 |
| `052` | 승인 → 승인 | 출력 잘림 → 승인 | 원본 호출은 280-token 상한에 도달해 JSON 파싱 불가; 의미 판정에서 제외 |
| `101` | **거부 → 거부** | **거부 → 거부** | 두 모델이 Cedar `in`을 직접 일치/집합 검사로 읽고 자손 계층을 놓친다고 설명 |
| `151` | 승인 → 승인 | 승인 → 승인 | 오류 관측 없음 |

각 칸의 정답은 **공식 데이터셋 gold를 승인**하는 것이다. mini는 원본 3/4, 정규화 3/4; 강한 모델은 원본 승인 1/4·거부 2·잘림 1, 정규화 승인 3/4이었다. 16 calls, mini 입력 3,322/출력 1,059 tokens·$0.0030232, 강한 모델 입력 3,322/출력 1,181 tokens·$0.016092; 합계 **$0.0191152**. 강한 모델 `052` 출력 잘림은 `finish_reason=length`; 재시도하지 않았다.

`case-101`의 원문은 파일 지역이 사용자 그룹과 같거나 그 자손일 때 허용한다. 정책은 `resource.region in principal.assignedGroup`이다. [Cedar 공식 문서](https://docs.cedarpolicy.com/syntax-operators.html)는 `in`이 전이적·반사적인 계층 연산자임을 명시한다. 따라서 모델의 거부 설명은 **Cedar 연산자 의미를 잘못 읽은 것**으로 보인다. C8에서 같은 정책에 직접/2단계 자손 요청을 넣어 실제 decision과 로컬 효과로 재확인한다.

스크립트는 모든 API 결과와 `result.json`을 저장한 뒤 **표준 출력 요약 생성 중** 잘린 JSON 응답을 `None`으로 취급하지 못해 exit 1이었다. `stderr.txt`에 남겼으며 모델 결과나 정형 검사는 저장 전 완료됐다. 이 실패를 숨기거나 같은 16호출을 재실행하지 않는다. C7은 독립 **전체 정책** reviewer 평가이지 AutoCedar 원본 atom별 ModelReviewer/인간 검토 결과가 아니다. 4-case 표본으로 184개 전체의 오류율을 추정하지 않는다.
