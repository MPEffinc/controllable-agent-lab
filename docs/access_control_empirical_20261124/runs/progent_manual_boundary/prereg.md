# Progent 원본 wrapper 최소 경계 실험 — 사전 등록

- 검증 질문: 원본 `secagent.tool.secure_tool_wrapper`가 수동 정책의 정상 인자를 허용하고 잘못된 인자를 실제 로컬 effect 전에 차단하는가? 같은 PEP에서 과권한 정책과 정책 미설정의 결과는 무엇인가?
- 원래 주장과 범위: Progent는 도구/인자 수준 정책 집행을 주장한다. 여기서는 정책 **생성**이나 SMT 업데이트, AgentDojo 공격 방어율을 시험하지 않는다.
- 정책 의도: `transfer(recipient='approved', amount=10)`만 승인. 실서비스 계좌가 아닌 임의 문자열을 쓴다.
- 관측 effect: 래핑된 함수가 호출되면 이 디렉터리의 임시 ledger JSON에 거래를 추가한다. 각 조건 전 상태를 비우고 전후 값을 저장한다.
- 예상 결과: 정확한 정책은 승인 인자만 ledger에 추가; 거부 인자는 ledger 변화 없음. 과권한 정책은 비인가 수취인 효과 발생. 정책 미설정은 소스의 경고 후 통과 가능성 확인.
- 반증 관찰: 정책을 통과하지 않은 비인가 인자가 ledger에 추가되거나, 승인 인자가 차단되면 집행 가설이 반박된다. 과권한 정책도 비인가 효과가 차단된다면 예상이 반박된다.
- 최소 비용: 원저자 로컬 venv의 Python 1회, 모델/API 호출 0, Docker/VM 불필요.
- 완료 조건: 4조건 정책, 결과, 전후 ledger, stderr 기록과 원본 소스 PEP 위치 연결.
- 재현 분류: **독립 로컬 컴포넌트 실험**. 원저자 논문의 end-to-end 실험 재현이 아니다.
