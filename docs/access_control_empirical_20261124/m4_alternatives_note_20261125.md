# M4 철회 출처의 agent write-back 재권위화: 대안 원문 독립 감사

2026-11-25 UTC, **원문 조사만** 수행했다. 이 문서는 Shen et al. `Revoked but Still Authoritative`의 저자 집계/코드 감사와 분리한다. 여기서 묻는 동일 문제는 *원본 출처가 철회됐는데 agent가 그 내용을 현재 journal/요약으로 다시 써서 retrieval filter가 새 문서를 유효하다고 고르고, 그 선택이 답변·tool 호출·외부 effect에 쓰이는가*이다. 원문·코드 평가에서 `retrieval selection`, `모델 context/답변`, `tool invocation`, `실제 effect`를 서로 다른 분모로 취급한다.

## 직접 대응과 전제

## 최종 효과·분산 철회 대응: retrieval 자체와 구별

| 대안 | 유효한 직접 보장 | M4 retrieval과의 차이 |
|---|---|---|
| [CONTINUITY §§3.3–3.5, 5.5, 6, Thm.4](https://arxiv.org/html/2609.05269) | authenticated root에서 ordinary derivation·summarization·memory consolidation은 execution authority를 늘리지 못하게 검증한다. 완전한 action/field binding과 finality sink의 최신 policy·revocation 재확인(C3–C7) 아래 protected **effect**를 막는다. | journal의 검색 결과가 잘못 골라지는 것을 막는 retrieval backend는 아니다. 잘못 고른 항목이 **권한 없는 tool effect**로 이어질 때, source/value provenance와 정확한 effect class를 sink까지 전달하면 직접 차단할 수 있다. TCB는 신뢰된 origin/provenance/release/transform issuer, 키, policy state, 모든 동등 effect 경로의 mediation을 요구한다. 논문 실험은 구성된 fault/model 범위이며 실제 Shen backend와 동일 입력 대조가 아님. |
| [Authorization Revocation §§3–5, Table 2 A1–A9](https://arxiv.org/html/2609.21284) | root-epoch cut, carrier/queue manifest, provider별 fence와 frontier 증명으로 철회한 root에 의존한 **뒤늦은 protected effect**를 막는 설계. 독립 권한 경로는 정확한 rebind가 가능하다. | 기억 항목의 source validity·검색 rank·정답을 직접 검사하지 않는다. M4에서 후속 행동이 구 root authority를 쓰는 경우에만 sink 효과 쪽 강한 조합이다. 모든 handoff의 support-provenance completeness(A4), 모든 runtime/provider/sink/channel의 manifest(A6), 원자적 fence(A5) 등이 전제. 저자 평가는 provider-free 17-case late-effect suite이며 실제 외부 provider commit/agent write-back retrieval 아님. |

## 출처 검사가 충분한가: 별도 선택 경로

[Selection Integrity for LLM Graph Memory §§II–VI](https://arxiv.org/html/2606.12290)은 **다른 공격 능력**인 *untrusted graph-structure write*가 authenticated record만 선택되도록 ranking을 바꿀 수 있어, 선택된 record의 provenance만 확인하는 IFC가 무력해지는 조건을 제시한다. AuthSelect는 인증된 subgraph로 native selector를 재계산한다. 이는 Shen의 `current journal` 재작성과 동일 실험은 아니지만, retrieval validity filter를 고칠 때 **검사할 객체가 선택된 item뿐인지, 선택 경로까지인지**를 분리하도록 요구하는 강한 반박이다. 논문은 sandboxed ledger의 28/499 잘못된 effect를 보고하지만 실제 은행/provider 지급과 혼동하지 않는다.

## 현재 M4 판정에 주는 영향

**추가 함수 대조(이번 세션):** [MAP-Graph 공개 보조 artifact의 원본 `gate_action()` 4입력](runs/H11_risk_metadata_20261125/result.md)에서는 trust .76의 supporting memory에 `revoked_ancestors=["revoked_source"]`가 정확히 들어오면 high-risk action을 `BLOCK`했다. 같은 support에서 revoked ancestor가 없으면 제안 action metadata에 따라 `ASK_USER`/`ALLOW`가 갈렸다. 이는 **계보 정보가 정확히 공급된 경우의 함수 경계**일 뿐 M4의 실제 journal ingestion에서 그 계보가 자동 수집된다는 증거가 아니다.

1. **좁은 실패 관측과 신규 Need는 별개다.** Shen의 저자 결과가 증명하는 것은 그 backend/설정에서 current journal write-back이 철회 source의 권위를 가릴 수 있다는 것까지다. 이 메모는 Shen raw trial을 재실행하지 않았다.
2. **조건부 기존 해결책이 분명하다.** 출처/파생 graph가 정확하고 철회 event가 code-owned로 들어오면 MAP-Graph의 ancestry-aware gate 또는 Audience-Bound의 currentness cascade가 같은 종류의 파생 항목을 다룬다. 효과에 한해서는 CONTINUITY/Authorization Revocation의 신뢰된 sink·fence가 보완한다.
3. **남는 반증 가능 질문:** 원문 텍스트에서 철회 event와 실제 read→write dependency를 **독립 oracle 없이** 안정적으로 수집하고, 잘못 쓴 current journal/요약은 제거하면서 정상 최신 journal은 보존할 수 있는가? 같은 Shen 사례에 (a) current-only filter, (b) source lineage+current validity, (c) ancestry/action gate, (d) code-owned event+snapshot, (e) full rebuild를 붙여 selection·답변·tool invoke·effect 각각의 분모와 비용을 측정해야 한다. 강한 대안이 같은 조건에서 성공하면 신규 메커니즘 Need 가설을 기각한다. 현재 **독립 신규 Need `UNVERIFIED`**.
