# Policy Verification / Correctness 조사 노트 (2026-11-23)

> 최종 산출물의 검토용 근거 노트. 논문 간 관계는 연대나 인용 자체가 아니라 *같은 실패 조건에 대한 메커니즘*으로 판단했다. 논문의 평가 수치는 해당 벤치마크와 모델에 한정한다. 형식 정확성(formal model·규칙), 의미 정확성(사용자/조직 의도), 집행 정확성(runtime effect)을 혼동하지 않는다.

## 핵심 계보와 해결 범위

### V-P1. 형식 정책 오류/확대: 기존 접근제어가 이미 상당 부분 해결

1. **P-V1:** 명시된 정책이 구문·타입 오류, 충돌, 예상치 못한 확대를 가질 수 있다. Margrave는 XACML 하위집합을 decision diagram으로 변환해 속성 및 변경 영향 분석([저자 PDF](https://web.cs.wpi.edu/~kfisler/Pubs/icse05.pdf), §1–3). ZELKOVA는 IAM 정책을 SMT로 표현해 속성·정책 관계를 검사([저자 PDF](https://kasperluckow.com/papers/fmcad2018.pdf), §I–IV). `ALTERNATIVE_APPROACH`/`EXTENDS`는 특정 형식/언어에 한정.
2. Cedar는 스키마 기반 오류 검사(§2.5)와 SMT 동치/포함 및 반례 요청(§2.6), 논문상 sound/complete symbolic encoding(§4.4)을 제공([원문](https://arxiv.org/html/2403.04651)). Cedar의 Lean 형식 모델과 Rust 코드 관계는 기계 증명+차등 테스트라는 별개 수준([FSE Companion 논문](https://arxiv.org/html/2407.01688), §3–4). `DIRECTLY_ADDRESSES` P-V1; 다만 Cedar 코드 전체가 기계적으로 증명되었다고 쓰면 안 됨.
3. 실제 agent 제품의 [AWS AgentCore Policy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-generation-validation.html)는 자연어→Cedar 변환 후 gateway 스키마 검사와 `INVALID`, `NOT_TRANSLATABLE`, `ALLOW_ALL`, `ALLOW_NONE`, `DENY_ALL`, `DENY_NONE` 결과를 제공(공식 문서 §§How it works/Common findings). 이는 구문/정형 과권한을 **이미 서비스에 적용**한 직접 반박이다. 문서는 생성 정책이 실제 사용자 의도와 같음을 증명하지는 않음. 제품 [GA 발표](https://aws.amazon.com/about-aws/whats-new/2026/03/policy-amazon-bedrock-agentcore-generally-available/)는 2026-03-03.
4. FORGE도 stratified-negation Datalog의 결정 의미, 재귀 경로, offline contradiction/redundancy 분석 가능성을 언급하지만 분석이 모든 재귀 정책에 완전하지 않다고 명시([원문](https://arxiv.org/html/2602.16708), §3.3). `PARTIALLY_ADDRESSES` P-V1. 결론: **정책 형식 검증 일반을 새로운 Need로 제시할 수 없음(`RESOLVED` for 지원 언어·모델 조건)**.

### V-P2. 정책의 *의미*가 사용자/조직 의도와 다른 경우: 부분 해결과 직접 관찰된 잔여 오류

1. ShieldAgent는 긴 규정 문서에서 GPT-4o로 정책/LTL 규칙을 추출하고 규칙 회로와 검증 도구로 action trajectory를 심사([원문](https://arxiv.org/html/2503.22738), §3.2.2, §5). **제한 B:** 추출된 규칙의 문서 의미 보존에 대한 독립적인 완전성 증명은 제시되지 않는다. 이것만으로 실패/취약점은 아님.
2. FORGE는 LLM 자연어→Datalog에서 누락·지원되지 않는 규칙·조건 오해를 명시 인정(A), clause-level traceability/back-translation/관측 행동 judge와 비교를 제안([원문](https://arxiv.org/html/2602.16708), §3.4, App. H.1). Judge는 번역기와 동일 기반 모델이며 독립 인간 명세를 측정하지 않는다고 명시(App. H.1). **재현된 평가 실패 D:** 구성 중 기록된 모든 결정에 judge와 일치했음에도 10개 번역의 held-out reward가 0.533–1.000, 표의 5개가 0.667–1.000; Task 43의 허용되어야 할 취소를 번역 규칙이 과잉 조건으로 막음. 구성 trace에 허용 취소가 없어 잘못된 규칙이 동등하게 보였음(App. H.3/Table 9). `EVALUATES` 정책 번역 검증의 충분성.
3. Text2NGAC은 네 NGAC 관계 추출과 구조 검사를 구현하고 918 변이 중 99.7%를 탐지한다고 주장([원문](https://arxiv.org/html/2611.12572), Abstract/§3/§5). 그러나 §5.2/Table 15의 **통제 변이 실험 D**에서 parent-entity abstraction (예: `patient_mid`→`patient_record`)을 11/120, 9.2%만 탐지. 이 fault는 형식·provenance·충돌 검사에 통과하면서 범위를 넓힌다(§5.2). 저자는 sentence-grounded review-routing heuristic이 이 변이 114/120을 flag한다고 보고하므로 해당 문제를 '전혀 해결 불가'로 주장하면 안 된다. `PARTIALLY_ADDRESSES` 의미 오류.
4. 같은 팀의 NGAC-IR은 Text2NGAC의 구조 검사 한계를 명시해 grammar-constrained IR, 결정적 컴파일, 출처 문장과의 back-translation 의미 비교를 추가([원문](https://arxiv.org/html/2611.26941), §1, §3). `EXTENDS`/`DIRECTLY_ADDRESSES` Text2NGAC의 의미 오독. 평가상 714문장의 95.7%가 원문 문장과 faithful, 검사로 실제 31개 오류 중 26개 탐지, 10.5% 문장 human review로 보냄(§5/Table 3, §5.3). **잔여 D/B:** 검사가 놓친 5개는 조건 누락 3, 잘못된 객체 1, 앞 문장에만 근거가 있는 목록 항목 1(§5.3). 저자는 grammar가 수량, delegation, 중첩 obligation을 표현 못하고 Policy Machine export는 조건을 검사하지 않는다고 명시(§6 Limitations). 따라서 static 문장→NGAC의 높은 정확성을 live agent/MAS 승인 정책으로 일반화할 수 없다.
5. AutoCedar는 사람이 또는 모델이 세분화된 target atom을 승인하고, 이후 verifier가 Cedar 정책을 해당 target과 비교([원문](https://arxiv.org/html/2607.03656), §III). 이는 명세가 올바른 *경우*의 강력한 대안. 221 CedarBench 과제 모두 수렴했고 독립 gold 200건 중 178건 동치(§V-D/Table VI). **직접 관찰된 D:** target 검증을 통과한 197개 중 19개는 target 자체가 gold를 잘못 포괄/제외해 동치 아님(§V-D); 저자도 source 요구 누락이나 잘못된 atom 승인이 있으면 잘못된 경계를 정확히 검증할 뿐이라고 명시(§VI). `PARTIALLY_ADDRESSES` V-P2; 조건은 검토자가 올바른 target을 확인할 수 있는 경우.
6. Reparo는 저장소 코드·주석·문서 증거를 모아 정책을 만들고 *다른 LLM*으로 행동 oracle을 만들어 테스트([원문](https://arxiv.org/html/2610.41800), §5.2). 228개 실제 저장소에서 공식 validator 통과율 99.0–100%, oracle 일치율은 언어별 76.3–99.6%(Abstract/§7). **제한 A:** 생성 oracle이 유한한 행동만 보며 저장소 증거도 누락/오류일 수 있어 실제 의도 증명은 아니라고 §9 명시. `ALTERNATIVE_APPROACH` V-P2. 이것은 FORGE의 동일 모델 judge보다 독립성을 높인 반박이지만 사용자 승인 원문이 비어 있거나 애매하면 더 많은 저장소 자료로 정답이 자동 결정되지는 않음(연구자 추론 C).
7. AWS AgentCore 생성 정책 검증은 원문 의미 검증과 같지 않다. 공식 문서가 “Review generated Cedar policies to ensure they match your requirements”라고 요구([Create a policy](https://docs.aws.amazon.com/bedrock-agentcore/latest/devguide/policy-create-policies.html)). 형식적 `VALID` 결과만으로 승인 정합성을 주장하면 오류.

**판정:** V-P2는 **`PARTIALLY_RESOLVED`**. (i) 원문에서 이미 명확하고 승인된 정형 target이 있으면 Cedar/AutoCedar가 정책 동치·범위를 검증할 수 있다. (ii) 자연어 원문에서 target을 생성하는 단계에는 FORGE의 held-out 오류, Text2NGAC의 범위 확대 변이, AutoCedar의 wrong-target, NGAC-IR의 실오류 5건이라는 직접 증거가 있다. `OPEN_WITH_EVIDENCE`라는 강한 판정은 **복수 소스와 런타임 재계획이 함께 있는 agent/MAS 조건의 독립 평가가 없음을 추가 확인한 뒤** 한정할 수 있다. 현재 '자동 의미 증명 일반 불가능' 식의 주장은 하지 않는다.

### V-P3. 집행/상태/관측의 정확성: 보장은 매개된 효과와 정확한 증거에 상대적

1. AuthGraph는 원래 user prompt+tool catalog만 보는 Planner에서 authorization graph를 생성하고, 실행 trace의 injected reasoning graph와 tool/parameter source를 비교([원문](https://arxiv.org/html/2605.26497), §3.1–3.4). Attacker는 원 사용자 지시·시스템 프롬프트·tool 정의를 바꾸지 못함(§3 Problem setup); clean-context isolation은 이 조건하의 주입 영향 차단이지 policy 의미 올바름의 증명은 아님. Replan은 whitelist 내부로 제한되지만 관측 내용을 Planner에 주며, 같은 authoritative source 자체가 오염된 경우는 범위 밖(§3.3/§5). AgentDojo GPT-4o에서 ASR 0.40→0.01, 무공격 utility 0.79→0.76; AgentDyn ASR 0.39→0.02, utility 0.51이라는 저자 평가(§4/Table 3). §5는 LLM attribution 오류 및 single-agent scope도 명시(A). `PARTIALLY_ADDRESSES` parameter-source 정합성, 내용 진실성·cross-agent provenance는 범위 밖.
2. FAVA는 LLM Permission IR의 evidence spans→graph, SMT로 finite graph의 forbidden label-to-sink 충돌을 검사하고 effect 전 gateway 집행([원문](https://arxiv.org/html/2607.27267), §FAVA Method/Finite-Graph Soundness). **보장은 생성 graph·고정 policy translation·gateway-visible action에 대해서만**(Finite-Graph Soundness/Security Assumptions). 완전 매개, capability-conformant backend, 정책 번역·sanitizer 신뢰가 요구됨. 801 binary 사례에서 DCR 90.5%; benign allow 57.7%, 69 false blocks(§Experiments RQ1, Discussion). **평가상 직접 오류 D:** `agents-inkline-type-guard`에서 repository별 test/export obligation이 IR에 누락돼 SMT가 허용(§RQ5/Figure 5). 저자는 concurrent tool calls, shell AST, TOCTOU도 prototype 범위 밖이라고 명시(§Discussion). `PARTIALLY_ADDRESSES` 특정 정형 graph 속성; 의미와 실제 효과는 다른 층의 확인 필요.
3. FORGE는 재귀 Datalog로 history/provenance와 MAS 간 의존성을 표현하고 effect 전 reference monitor에서 결정([원문](https://arxiv.org/html/2602.16708), §3–4). 결정의 정형 보장은 *candidate action의 완전 매개*와 *fact의 충실한 관측*에 의존(§3.1/§4.4); §7.1은 join point 외 raw socket/stdio, advised method 내부 동시성으로 graph가 불완전할 수 있음을 인정(A). 이것은 무조건적인 우회 실패 D가 아니라 명시된 보장 조건. OS/API/서비스 경계 등 다른 계층과 조합해 확인할 문제.
4. Agentproof는 네 agent framework의 graph를 추출해 구조 검사 및 graph×DFA로 모든 추상 경로의 temporal safety를 검사([원문](https://arxiv.org/html/2603.20356), §5–6). 18개 *저자 구성* workflow, 27개 stub extractor 검사; 27% 구조 결함, 55% human gate 위반은 실제 시스템 유병률 아님(§7, §9). **제한 A:** LLM 출력의 사실성/의도는 증명하지 않음, human-node naming heuristic, runtime graph mutation 시 재검증 필요, DSL에 실시간 범위/과거 시제 없음(§9). `PARTIALLY_ADDRESSES` workflow topology·정형 temporal property만. 어떤 정책을 검증할지는 별개.
5. Temporal RV 논문은 MFOTL/MonPoly로 AgentDojo·STAC·R-Judge 기록을 *offline replay*만 수행([원문](https://arxiv.org/html/2610.09793), §1 Scope/§3). 5개의 일반 obligation이 STAC attack chain 71.8%, AgentDojo 성공 공격 70.1% flag, benign 29.3%도 flag(Abstract/§4); 기록에 승인·타임스탬프가 거의 없어 역사적 판단을 실질적으로 할 수 없다고 분석. §5의 controlled poisoning에서는 provenance 한 줄로 순진한 검사가 94–99% 회피되나 lookup-bound spec으로 테스트한 회피를 차단(§5). 이는 `EVALUATES` 관측정보와 증거 무결성, 또 `DIRECTLY_ADDRESSES` 해당 *특정* provenance poisoning. **실시간 agent 적응/실제 효과는 미평가**(§1 Scope), 따라서 in-loop 집행 결과라고 쓰면 안 됨.
6. ASU는 정확한 효과 descriptor를 신뢰 경로에서 렌더하고 signed approval에 결속, gateway가 저장한 call을 실행([원문](https://arxiv.org/html/2610.21063), §5–7). Tamarin 증명은 명시한 세 신뢰 가정 하 binding/single-use/key-level 비부인성을 포함(§6). 10 runtime audit에서 8개는 binding을 측정 가능, 그중 4개에서 승인 후 argument 수정 가능하다고 저자 보고(§4). 27,108 scripted trials/609 AgentDojo pairs에서 대체·재생 차단(§7); 실제 사람 연구는 아님(§8.3). **강한 반박:** approval과 실행 동작의 결속 자체는 이미 해결 가능. 그러나 저자도 승인 없이 정책이 이미 허용한 효과는 승인 메커니즘으로 막지 못한다고 명시(Abstract/§7.6). 의미상 과권한 정책은 다른 문제.

**집행 정확성 판정:** 각 경계의 정형 보장은 상당 부분 `RESOLVED`/`PARTIALLY_RESOLVED`; 전체 실제 효과 보장의 미검증 조건은 완전 매개·증거 무결성·service-side effect contract 및 동시성. 특정 논문의 관측 누락만으로 새 Gap 주장 금지. ASU, FAVA, FORGE, runtime monitor, 서비스측 정책 및 기존 분산 시스템 메커니즘을 대안으로 대조해야 한다.

## 분리해야 할 사실과 가설

**문헌상 확인된 사실:** (a) 형식 정책의 syntax/type/inclusion 및 일정한 workflow topology/trace 조건 검증은 기존 기술로 수행 가능. (b) 자연어 번역의 의미 정합성 검사는 개선되었지만 원문 근거 누락·불완전한 target·유한 oracle·잘못된 출처 판단 때문에 평가상 오류가 남아 있다. (c) 검증 보장은 항상 모델/정책/관측/매개 범위에 상대적이다. (d) 정확한 승인 동작 결속은 ASU 같은 방법으로 가능하다.

**아직 가설:** 하나의 agent/MAS 작업에서 user 승인, 조직 정책, runtime replan, cross-agent delegation, tool-description/implementation, downstream service effect를 연결한 정합성 검증이 기존 기법의 적절한 조합으로도 불충분한지. 개별 논문에서 각 조건이 다뤄졌고, 통합 평가 부재만으로 새 연구 Need를 확정할 수 없다. 최소 추가 문헌 확인: per-task target에 독립 인간 oracle을 둔 기존 연구, tool implementation/effect contract 검증(예: ContractGuard)의 학회 원문, in-loop service effect와 동시성·승인 갱신의 end-to-end 연구.

## 추가 조사: 맥락이 바뀌어도 승인을 재사용하는 경우의 동의·효과 결속

### 일곱 반박 적용

1. **이미 해결?** 사용자 선택에 따른 scoped 재사용은 ConLeash, 정확한 효과의 실행 시점 승인은 CTA, cross-layer 결속은 CONTINUITY, provider frontier는 EffectBound가 상당 부분 다룬다. `RESOLVED`라고 하기에는 ConLeash §9가 추상화 오류·시간/도메인 속성 미지원, CTA §6이 누락된 정책 사실의 문제, CONTINUITY §12가 semantic correctness·실제 provider 부재를 명시한다.
2. **단순 구현 누락?** GitHub 사례는 REST SHA precondition을 쓰면 해결되므로 그 구체 경로는 구현·인터페이스 선택 문제에 가깝다(EffectBound §I, Table III). 다른 서비스도 provider gate, transactional check, taint/provenance 조합으로 해결 가능성을 배제할 수 없다.
3. **잘못된 정책 문제?** CTA의 보호 범위는 정책이 선언한 사실에 국한된다(§2.2, §6). “script content/digest가 승인에 중요하다”를 올바르게 명시하면 기존 exact-effect binding이 작동할 수 있다. 핵심 잔여 질문은 그 중요 사실을 어떻게 정당하게 얻고 최신으로 유지하는지이지, 단순히 기존 prover가 틀렸다는 뜻은 아니다.
4. **위협 모델 밖인가?** ConLeash의 세션 내 MCP 재사용과 Consent 논문의 세션/작업 간 residual grant, IntentCap의 현재 작업 단기 lease는 서로 다른 범위. 한 연구가 평가하지 않은 cross-task 실행을 그 연구의 실패로 단정하지 않는다.
5. **관측·표현·집행 어느 부분?** ConLeash는 추상화/표현(시간·도메인 조건), CTA는 정책에 필요한 premise의 완전성, CONTINUITY는 context manifest와 신뢰한 semantic validator, EffectBound는 provider 도구가 effect frontier를 조건화·재검사할 수 있는지에 각각 경계가 있다. 막연한 “집행 지점 없음”이 아니다.
6. **전통적 기술?** UCON의 사용 중 재평가, Cedar/ABAC의 선언적 조건, capability attenuation/expiry, provider-native conditional write/transaction, TOCTOU 방어가 직접 대안이다. CTA §7/Table 15와 EffectBound §II/§VI는 이를 자체적으로 비교한다. 이 기술들을 제대로 구성해도 남는 실패 조건의 독립 검증은 아직 없다.
7. **왜 중요?** Consent 논문 §5.4의 실제 코딩 agent 55사례와 §5.3의 고정된 benign history 비교는 승인 재사용이 공격 실행 가능성을 바꿀 수 있음을 보여준다. 반면 ConLeash §8.3은 범위를 좁힌 반복 승인에 대한 사용성 이득, CTA §5.2의 별도로 승인된 fallback, EffectBound Table III의 정상 완료를 보여준다. 따라서 정상 업무를 유지하며 통제할 이유는 실증되지만, *새로운 방법론이 반드시 필요하다*는 증거는 아니다.

**후속 문헌에서 필요한 최소 확인:** 같은 작업과 tool argument를 유지한 채 코드/의존성/설정/프로젝트/서비스 상태만 바뀐 longitudinal trace에 ConLeash의 정확한 boundary 추상화, CTA의 선언된 premise·effect binding, CONTINUITY의 signed transformation, provider-native conditional operation을 각각 적용한 원문 비교가 있는지; 오류가 있다면 (i) 필요한 사실의 의미적 선택, (ii) 관측 지연/불완전성, (iii) 정책 표현, (iv) effect frontier 제어 중 어느 원인인지. 비교를 발견하지 못한 것만으로 부재를 증명하지 않는다.
