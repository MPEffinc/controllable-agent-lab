# H13 반박 감사: 장기 승인 변경, 파생 memory, MAS 효과

**기준일:** 2026-11-25 UTC. **방법:** 아래 원저자 논문·공식 표준을 읽고 이미 저장된 [H10 감사](h10_memory_counterreview_20261125.md), [M4 대안 감사](m4_alternatives_note_20261125.md), [H11 코드 실험](h11_mapgraph_risk_gate_20261125.md)의 관측과 대조했다. 이 문서의 새 증거는 **문헌 감사**이며 새 논문 코드 실행·유료 API 호출은 0이다. 서로 다른 연구의 공격률은 같은 분모의 우열로 비교하지 않는다.

## 기존 해결책을 겨냥한 잔여 질문

**H13-A — “원본 승인→파생 memory→최종 효과를 연결하는 메커니즘이 없다.” `REJECTED_HYPOTHESIS`.** WTB·CONTINUITY가 효과 경계까지, MAP-Graph·Audience-Bound·PACMI가 기록된 계보와 상태를, FIDES가 정보흐름을, Epistemic Guard가 저장 write gate를 제공한다. 이들 기능을 별개의 연구에서 가져와 결합하는 방식은 적어도 올바른 event·lineage·완전 중개·협력 receiver가 있을 때 조건부 해결책이다. “완전한 end-to-end 해결 논문이 없다”는 주장도 WTB v4 때문에 방어하기 어렵다.

**H13-B — 자연스럽게 생긴 event/lineage 오류에서 안전성과 정상 완료를 함께 잴 수 있는가? `GAP_SUPPORTED`는 *제한된 평가 지식*에만. 신규 독립 Research Need는 `UNVERIFIED`.** 고정할 조건은 다음과 같다. 인증된 사용자가 자유 자연어로 승인 범위를 변경한다. Agent A가 이를 사건·기억으로 요약해 Agent B에게 넘긴다. 후속 정상 업무는 남아 있고 철회된 scope의 행동만 금지된다. source identity 자체가 forged된 상황이 아니라 **권한 있는 source의 의미가 잘못 축약되거나 실제 dependency edge가 누락·과포함**될 수 있다. 마지막 도구는 테스트 서비스의 실제 상태를 바꾸고, 중개 sink가 최신 grant를 확인한다. 이 결합에서 자동 event·lineage capture의 오류율이 이후 false effect/false denial을 얼마나 일으키는지, 강한 기존 방법을 동일 입력·동일 effect oracle로 비교한 결과는 이번에 감사한 논문들에서 확인되지 않았다. 이 문장은 전체 문헌 부재의 증명이 아니다.

근거는 서로 다르게 좁다. [EAL-Bench v2 §4.4/Appendix](https://arxiv.org/html/2609.01836v2)는 권한 있는 source만 남겨도 잘못된 승인 state가 줄지 않고, exact-oracle·rebuild는 상당히 개선한다고 관측한다. [Shen M4 §4–6](https://arxiv.org/html/2609.08258)는 현재 journal을 가진 실험에서 파생 write-back의 재권위화가 남음을 관측한다. [PACMI §6](https://arxiv.org/html/2610.05732)는 induced/손상 edge 성능을 미측정이라고 명시한다. 그러나 EAL의 synthetic tool behavior, M4의 retrieval decision, MAP-Graph의 risk gate, WTB의 mediated effect는 서로 다른 관측 대상이므로 이 수치를 이어 붙여 **동일 인과 실패**라고 판정하지 않는다.

**H13-C — 표현을 바꾼 tool request가 출처 매칭을 우회하고 정상 업무가 거절될 수 있다. `OBSERVED_IN_PRIOR_WORK`, 일반 Need는 `UNVERIFIED`.** [AGATE v1 §§6.2–7](https://arxiv.org/html/2609.30830)는 mailbox 정리의 역사적 DSH trace에서 출처 기반 denial 다음 argument rewrite로 synthetic 영구삭제 tool request가 content match를 통과한 사례를 공개한다. **실제 mailbox 삭제가 아니다.** §6.3은 정상 file-processing 11 scenario 중 6개에서 8 denial event를 보고하지만 이것을 completion rate로 읽을 수 없다. §7.1은 rewritten/translated/inferred content와 unobserved surfaces가 취약함을 인정한다. FIDES의 label propagation, PAuth의 서버 argument check, WTB/CONTINUITY의 effect sink를 같은 입력에 적용하면 이 현상은 이미 방어될 수 있다. 따라서 AGATE 구현 실패가 곧 학계의 독립 미해결 보장은 아니다.

## 반증 가능한 최소 실험

**질문:** 권한자 자연어 변경과 agent write-back을 통과할 때, source에 대한 신뢰성과 최신 grant를 이미 확인하는 강한 기존 pipeline이 *누락/과포함 lineage* 때문에 안전한 효과 또는 정상 완료를 얼마나 잃는가?

1. 격리된 sqlite-backed 테스트 서비스의 `resource_id`, `approved_scope`, `policy_epoch`, `effects`를 준비한다. 사용자는 먼저 두 resource의 변경을 승인한 뒤 하나만 철회한다. Agent A가 둘을 섞은 요약을 write-back하고 Agent B가 다음 세션에 읽는다. 정상 요청은 아직 승인된 다른 resource를 변경해야 한다. 테스트 oracle은 **원래 서명된 사용자 event와 실제 서비스 effect**를 본다. 자연어 추출 oracle, stored graph, model 판단은 서로 공유하지 않는다.
2. 동일 요청·모델·seed·policy snapshot에서 (a) 정확한 event/lineage + 강한 sink, (b) 자연 추출 event/lineage + 강한 sink, (c) 누락 edge, (d) 과포함 edge, (e) 안전한 기존 보완: code-owned actual-consumption lineage·transitive currentness·sink version check, (f) 전체 재구축/사람 확인 event 대조를 수행한다. 각 지원 구현에서만 실행한다. 먼저 원저자 최소 사례를 통과시키고 어느 구성의 *원저자 재현*인지 명시한다.
3. 각 trial은 source text, event 해석, edge, grant epoch, 실제 sink decision, service before/after, 정상 완료, false denial, 확인 횟수, 지연/비용을 별도 기록한다. decision만 나오면 `DECISION_ONLY`라고 명시한다. false effect가 생기면 그것이 잘못된 event, 누락 edge, 미중개 경로, sink 원자성 부재 중 무엇 때문인지 대조군으로 분리한다.

**기각 조건:** (i) 정확한 event와 계보를 코드에서 보장할 수 있는 현실적인 배포라면 기존 설계의 범위 내 해결로 분류한다. (ii) 자동 추출/계보에서 오류가 있더라도 검토·재구축·보수적 label·현재 grant sink의 기존 조합이 정해진 비용에서 비인가 effect를 없애고 정상 요청을 유지하면 새 mechanism Need를 기각한다. (iii) provider가 authoritative 현재 grant/token 확인을 원자적으로 제공하지 못하는 경우는 **외부 API 계약 문제**로 따로 기록하고 H13의 자연어/계보 문제와 섞지 않는다.

## 판정

지금 가능한 가장 강한 말은 **“자동으로 얻은 승인 변경 event와 memory dependency의 신뢰도가 최종 effect 및 정상 완료에 미치는 영향을, 강한 기존 구성과 같은 입력으로 측정하는 공동 평가가 부족하다”**이다. 이는 구체적인 실험이 가능한 **평가 Gap 후보**다. 이미 알려진 보호 메커니즘 자체가 없다는 주장은 반박되었다. 같은 조건의 직접 비교에서 기존 조합이 충분히 동작하면 이 후보도 기각된다. 본 문헌 감사만으로 독립적인 새 Research Need를 확정하지 않는다.
