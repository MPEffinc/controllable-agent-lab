# C5 강한 모델 정책 검토 대조

2026-11-25 UTC. [사전등록](prereg.md)대로 C4의 같은 공식 AutoCedar `case-011` 요구사항·정답 정책·연구자 변이 6개, 순서와 prompt를 그대로 사용했다. 모델만 `gpt-4.1-2025-04-14`로 바꿨다. [실행 코드](run.py), [원시 요청/응답](raw.jsonl), [전체 판정](result.json), [표준 출력](stdout.txt)을 보존했다. C4의 gold/오답·이전 모델 응답은 입력에 넣지 않았다.

| 항목 | 관측 |
|---|---|
| 검토 verdict | **6/7**; `p0` 정답 정책만 거짓 거부, 여섯 변이는 모두 거부 |
| C4 저가 모델 | 동일하게 **6/7**, `p0` 거짓 거부 |
| 독립 gold를 받은 원본 AutoCedar verifier | C4에서 **7/7**; 정책 동치·포함 대조 |
| C4 로컬 Cedar/SQLite 효과 | `p0` 정상 merge 허용·비인가 witness 차단; `p1–p5` 각 witness 비인가 merge; `p6` 정상 과거부 |
| 사용량 | 7 calls, 입력 1,770 / 출력 1,026 tokens, 추정 **$0.011748** |

강한 모델은 정답 `p0`의 `!(true) || (principal != resource.author)`를 항상 참이라고 잘못 설명했다. 실제로 `!(true)`는 false이므로 전체 식은 `principal != resource.author`와 같다. `approvalCount >= 0`은 같은 conjunction의 `>= 1`을 무력화하지 않는다. 이 오해는 C4의 저가 모델에도 있었다. `p2` 응답에서는 강한 모델이 전자의 정확한 단순화를 말했지만, `p0`에서는 정반대로 판단했다. **모델의 설명 자체도 같은 실행 내에서 일관되지 않았다.**

**판정:** 원본 형식의 정답 정책을 자연어로만 검토하는 이 고정 세트에서는 모델 교체만으로 정상 정책 거짓 거부가 해소되지 않았다. 이는 두 모델·단일 공식 case·여섯 연구자 변이에 대한 재현 가능한 관측이다. 저자 생성의 19개 오류, 인간 reviewer, 실제 GitHub 서비스의 성능으로 일반화하지 않는다. 독립 gold+기존 정형 verifier는 이 경우를 해결했다. 다음 C6은 형식 도구로 동치 확인한 간단한 정규화가 같은 모델 검토를 고치는지 시험한다. 새 메커니즘 Need는 아직 `UNVERIFIED`다.
