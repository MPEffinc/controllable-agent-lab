# 검증 큐

순서는 증거 확보 비용과 의존 관계다. Gap 중요도 순위가 아니다.

| ID | 질문·사전 예측 | 완료 기준 | 상태 |
|---|---|---|---|
| A1 | H1–H14의 안전성·적용성·정확성/정상성·시스템 기여를 각각 다시 판정. 좁은 구현 실패와 신규 Need를 분리할 것으로 예상 | 각 가설에 최초 근거, 직접 관측, 최강 반박, 미검증 조건, 기각 조건을 기입 | 진행 중 |
| A2 | K01–K15 밖의 강한 해결책이 H13/H14와 시스템 계층 문제를 이미 해결하는가 | 원문 절·코드·평가 경계와 같은 문제 여부 기록 | 진행 중 |
| A3 | 연구실 ALPS/KubeAegis/KubeTeus/Bambda/POLARIS/ARES의 실제 PEP·정책·한계를 MAS 연구와 비교 | 원문·공식 코드 여부·제약을 source registry 및 비교표에 기입 | 진행 중 |
| A4 | 안전·정상·비용을 같은 입력에서 측정할 후보가 무엇인가 | RQ/위협/최강 대안/성공·실패 기준을 가진 상위 2–3개 선택 | 미착수 |
| B1 | 실제 LLM이 자연어 승인/철회와 비신뢰 도구 출력 아래 어떤 정책·행동을 생성하는가 | 사전등록, 원시 요청/응답·토큰·비용, 정상/비인가·강한 PEP, 로컬 서비스 전후 상태 | 미착수 |

각 실험의 실패가 기존 방법으로 해결되면 그 조건의 Need를 기각한다. 저자 코드와 독립 adapter를 혼동하지 않는다.
